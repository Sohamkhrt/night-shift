I can see the full test now. There's a subtle logic bug here. When `files=0`, `stat_output=""` which parses as `DiffStats(0,0,0)`. Then `max_files = max(0, -1) = 0` and `max_lines = max(0, added + removed - 1)`.

The `assume` check: `files(0) > max_files(0)` → False. So the assume only passes if `(added + removed) > max_lines`. But `max_lines = max(0, added + removed - 1)`. If `added=0, removed=0`: `max_lines=0`, and `0 > 0` is False → assume fails → example filtered. If `added=1, removed=0`: `max_lines=0`, and `1 > 0` → assume passes. But `stat_output=""` because `files=0`, so `_parse_diff_stat("")` returns `DiffStats(0,0,0)`. Then `check_diff_limits` gets `stats.total_lines=0 > max_lines=0` → False! So it **does NOT raise**, which means `pytest.raises(OverLimitError)` FAILS.

This is the actual logic bug: when `files=0` but `added+removed > 0`, the test builds `stat_output=""` (treating it as "no changes") but tells `check_diff_limits` that `max_lines < added+removed`. Since `stat_output=""` is parsed as 0 lines, the limit check sees 0 lines against a limit of `added+removed-1`, which never raises. The fix: when `files=0`, we must also filter out cases where `added + removed > 0` via `assume`.
